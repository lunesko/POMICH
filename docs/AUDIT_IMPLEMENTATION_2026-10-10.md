## Условия выпуска

1. До запуска новой версии выполнить миграцию. Официальный `scripts/deploy_remote.sh` делает это автоматически. При ручном обновлении: `docker compose -f docker-compose.production.yml --env-file .env.production run --rm --no-deps pomich-app python3 -m bot.migrate`.
2. Дать UID/GID 10001 право записи в смонтированный data. Deploy scripts выполняют chown каталога приложения; секреты и PostgreSQL volume не пересоздаются.
3. Все старые stateless cookies/bearer будут отклонены: пользователям потребуется повторный вход. Новые сессии проверяются через БД, отказ БД означает отказ авторизации.
4. Старый frontend не совместим с новым контрактом создания и realtime URL. Backend и frontend нужно обновлять согласованно. Обновить открытые вкладки после выпуска.
5. Настроить production SSH host/user/credentials и проверенный known_hosts. Значения не выдумывались и секреты не менялись. Испытать deployment/rollback на стенде с PostgreSQL.
6. Новые таблицы добавляются без удаления старых; при откате на старый код отозванные токены снова проверялись бы stateless. Такой откат отменяет защиту logout: заранее предусмотреть смену signing secrets или оставаться на исправленной версии.

## Что не закрыто

F14 (декомпозиция крупных модулей), F16 (полная browser→backend→PostgreSQL цепочка заказа), F19 (утверждённые retention/processors/deletion procedures) остаются открытыми. Добавленная PostgreSQL API-регрессия не заменяет полноценный E2E жизненного цикла. Для F11/F12 остаётся прогон на PostgreSQL и эксплуатационная проверка; для F04/F06/F07/F13/F17/F18 ограничения указаны в таблице. На странице privacy раскрыты прямые запросы к картографическим сервисам, но это не заменяет согласование сроков хранения и процедуры удаления с оператором.

Также остаются ручные device/accessibility проверки, реальные OTP/Telegram/GPS, production restore drill и настройка мониторинга. Наличие локальных исправлений не означает закрытия всего F01–F21 или готовности к массовому запуску.

## Валидация

### Дополнение 10.10.2026

После первичного отчёта выполнены PostgreSQL/PostGIS и контейнерные проверки. Исправлена ошибка
проверки результата `INSERT ... ON CONFLICT`, из-за которой конкурентный idempotency key мог
считаться вставленным при `rowcount=-1`. PostgreSQL-регрессии проходят, включая четыре
одновременных запроса, межпроцессный realtime, ротацию сессий и общий лимит соединений.

Реализованы rotation/replay detection refresh-cookie, отзыв семейств при отключении аккаунта,
ограничение realtime-соединений, экспорт и удаление данных клиента, а также автоматическая очистка
завершённых/отменённых заявок через согласованные 180 дней. Полный браузерный сценарий на настоящем
API и PostGIS проходит создание, предложение партнёра, подтверждение цены, все статусы до
завершения и отдельную отмену.

Production-образ собирается из hash-pinned Python lock, запускается UID 10001 с read-only root,
проходит readiness и проверку согласованности assets. Trivy не выявил CRITICAL; 44 HIGH относятся
к пакетам базового Debian trixie и не имеют доступной исправленной версии в отчёте сканера.
Добавлены SBOM и блокирующий CI-скан исправимых HIGH/CRITICAL. Внутренние метрики теперь явно
сигнализируют dead letters, очередь старше десяти минут и недоступный PostgreSQL realtime listener.

Не выполнены внешний production deploy/rollback, реальная отправка Telegram/OTP, ручная проверка
физических устройств и подключение сигналов к операторскому paging-сервису: для этого нужны
production SSH, секреты и выбранный канал оповещения. Декомпозиция крупных legacy-модулей F14
частична; критические account-admin и request-contract части уже вынесены.

При проверке не создавались production-заказы, не отправлялись сообщения и не менялись реальные профили. PostgreSQL, контейнерный runtime и production-развёртывание локально не проверены: Docker daemon/SSH environment недоступны.

- Frontend: 391 тест в 53 файлах; TypeScript и production build проходят.
- Backend: 290 тестов проходят; один тест двух процессов PostgreSQL пропущен локально и включён в CI. Остаётся предупреждение Starlette о будущем переходе TestClient с httpx на httpx2.
- Browser: два CSS/layout smoke и два production CSP smoke (desktop/mobile Chromium) проходят. Скриншотные эталоны Linux на Windows не перегенерировались.
- `npm audit`, `pip-audit` runtime/dev: известных уязвимостей не найдено на момент проверки.
- Проверены `git diff --check`, синтаксис deployment shell scripts и `docker compose config --quiet`.

Outbox dead letters требуют наблюдения и разбора оператором; автоматического бесконечного повтора нет. PostgreSQL broker использует отдельное соединение на процесс. Bootstrap JS отдаётся с no-store; frontend/backend и nginx CSP следует выпускать вместе.
