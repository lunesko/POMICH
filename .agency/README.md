# POMICH — агенты проекта

Установлены четыре роли из адаптированного набора Agency Agents. Приоритет имеют задача пользователя и действующие инструкции репозитория.

## Распределение

| Роль | Назначение | Профиль |
|---|---|---|
| pomich-backend-architect | Проектирует и исправляет диспетчеризацию, API и SQL-контракты POMICH. | [Открыть](profiles/pomich-backend-architect.md) |
| pomich-code-reviewer | Проверяет изменения POMICH на ошибки контрактов, прав, геоданных и realtime. | [Открыть](profiles/pomich-code-reviewer.md) |
| pomich-test-automation | Проверяет пользовательский путь и отказные сценарии POMICH через pytest и Playwright. | [Открыть](profiles/pomich-test-automation.md) |
| pomich-release-verifier | Собирает доказательства готовности конкретного изменения POMICH к выпуску. | [Открыть](profiles/pomich-release-verifier.md) |

## Порядок работы

Прочитай COMMON_RULES.md и профиль подходящей роли. Для реализации и исправлений используй инженера; для независимого review — reviewer; для тестов — QA; для проверки выпуска — release verifier. Для небольшой задачи достаточно одной роли. Не запускай весь процесс и других агентов автоматически.

Каждый профиль содержит контекст и общие правила, поэтому работает и при отдельной передаче ИИ. Храни фактические результаты в задаче/PR: commit, команды, статусы, доказательства и непроверенные ограничения.

## Форматы

profiles/*.md — инструкции, которые можно прочитать напрямую. Корневой AGENTS.md указывает, какой профиль выбрать. codex/*.toml — эквивалентные custom-agent профили, подготовленные для явного импорта в поддерживающий их клиент. Регистрация TOML в конкретной IDE не проверялась; само наличие файлов не запускает агентов. Глобальные настройки компьютера этим изменением не модифицированы.

## Проверка установки

Проверены четыре уникальных профиля, TOML parsing, совпадение инструкций Markdown/TOML и ссылки корневого AGENTS.md. Приложение не менялось; runtime-тесты этой установкой не заявляются.
